# Document conversion formats

[Acceptance](corpus-database-acceptance.md) verifies retained bytes and their indexed projections. This contract adds no schema and changes no frozen `model` or `run` type. New format structs belong to their producer packages. M1.13 owns the proposed candidate, recipe, policy, report, and synthetic decision-scope codecs; M1.14 composes their producers with the stores.

## Canonical hashing

Every digest is lowercase hexadecimal SHA-256 of exact retained bytes. Every `model.AssetRef.ByteSize` is the exact byte count. A hash identifies content, not its logical role or storage path.

| Rule | Bytes and validation |
|---|---|
| A, typed JSON | `encoding/json.Marshal` of the exact declared Go type, in declaration order, with standard escaping and no indentation. Frozen model types have exported field names, not snake-case tags. Decode with unknown-field rejection, reject trailing values, re-encode, and require byte equality. Preserve the producer's distinction between `null` and `[]`; do not normalize already hashed M1.12 arrays. |
| B, policy JSON | Recursively sort object keys in byte order; emit keys and strings with Go JSON escaping, integers in base ten without leading zeros, booleans as JSON literals, arrays in specified order, and no whitespace. Reject duplicate keys before JSONB insertion, unknown keys, nulls, floats, and exponent notation. Read JSONB numbers without float conversion and recompute the same bytes. |
| C, opaque bytes | Hash unchanged bytes. No JSON decoder or text normalization applies. This includes originals, text, decoded package members, and converter recipe bytes. |

Proposed rule A structs use the field spelling and order below, with no JSON tags or `omitempty`. Arrays are non-null; optional pointers encode as `null`, optional strings as `""`. All hashes are `model.Digest`, references are `model.AssetRef`, and ordinals are nonnegative integers unless stated otherwise. Required strings cannot be empty. M1.13 publishes byte fixtures for every format and absence case, and consumers freeze against them.

Not every coded object has a version field. `blocks-v1` governs its nested arrays and objects; the request and sandbox manifest have an external v1 contract. Never add an invented `schema_version` field to these bytes. For proposed structs the first field is `SchemaVersion` with the table's string value. Unknown versions reject.

## Conversion outputs

The coded baseline is `internal/corpus/conversion/` at merge `b7ca18d72bdfbeb7dce58313391e4615f4115bd5`, PR #37 head `743bc990d80a3b546572001ff6bfe874dd6d3219`. Its [M1.12 evidence](../plans/vietnam.md#m112-block-conversion) owns the hosted results and remaining gates. The format implementations are `blocks.go`, `maps.go`, `convert.go`, and `validation.go`. At that revision, synthetic inputs are [minimal.html](../../internal/corpus/conversion/testdata/minimal.html) and [document.xml](../../internal/corpus/conversion/testdata/document.xml); [expected.json](../../internal/corpus/conversion/testdata/expected.json) pins canonical block hashes and source ranges in `TestCanonicalBlockHashFixture` in `convert_test.go`. `TestBlockAdaptersDeterminismAndAnchors` and `fixtureDOCX` in `blocks_test.go` cover deterministic output and package those XML bytes as DOCX. These fixtures prove coded contracts, not real-document qualification.

`ConversionManifest` declaration order is `RequestKey, Request, ObservationKey, ArtifactRole, Language, HTMLSelector, DetectorHash, CandidateDigest, OutputBytes`. `Request` is `api.ConvertRequest` with `Artifact model.CaptureRef`, `Recipe model.AssetRef`, and `Budget model.ResourceBudget`. `DetectorHash` pins the detector recipe. The request digest names the result directory. Retain the full `CaptureRef`, including its transport receipt, media type, and capture identity; an original `AssetRef` alone cannot reconstruct this request.

The output manifest is strictly ordered by `Path`, with no duplicate path. Both result files are required. Other outputs use `objects/<digest>`. Its JSON bytes are at most `min(OutputBytes, 1 MiB)`; member count is at most `Budget.MaxItems`, and aggregate member bytes are at most `OutputBytes`. The converter validates exact hashes, lengths, semantic bindings, and source claims in the sandbox before calling retention. Manifest closure permits the captured original as an external source anchor. Every other referenced conversion object is a member; unused members reject.

`document.json` binds `SchemaVersion = blocks-v1`, the exact original `CaptureRef`, observation, artifact role, candidate digest, and converter recipe digest to the request. `DetectorHash` names the detection result, not the request's detector recipe. `Blocks` is `[]model.Block`; `NormalizedBlocks` names its rule A encoding. `RawBlocks` names an array of structs in order `ID, Kind, Text, Sources`. `RawText` and `NormalizedText` name aggregate bytes formed by concatenating blocks without separators. `OffsetMap` and `EditLedger` name `[]model.OffsetMapSegment` and `[]model.EditLedgerEntry`.

Each block has ID `block-<six-digit minimum ordinal>-<digest>`, where the digest hashes rule A `[]string{"block-v1", kind, raw, normalized}`. Its ordinal is its array index, parent is empty, authority is `unknown`, language equals the request, content is nil, and findings are nil. `RawText` is inline; `NormalizedText` names the per-block text object. HTML source spans use original-byte ranges. DOCX emits two spans with the block ID and matching token ordinals: an original anchor with `Member = word/document.xml`, `Object = paragraph/<ordinal>` and `BYTE_MAPPING_UNAVAILABLE`, then a decoded-member range in the retained XML object. Member bytes are not ZIP byte offsets.

Maps are per-block, not aggregate-document offsets. `source-decode-v1` maps source spans to a raw block object. `identity-v1` or `nfc-crlf-v1` maps that raw object to a normalized block object. Segment `Ordinal` is its index in the complete map. Raw block spans have `Object = text`. Nonempty normalized spans have an empty `Object`; empty normalized spans have `Object = text` and `BYTE_MAPPING_UNAVAILABLE`. Both text span kinds have empty `BlockID`. No map invents positions in aggregate text.

A changed block emits one `model.EditLedgerEntry` with `Kind = normalize`, sequential `Ordinal`, `Rule = nfc-crlf`, `Version = 1`, one input and one output spanning the full nonempty block objects, and non-nil `Removed` and `Replacement` references. `Evidence` names the rule A `model.DecodedEdit` carrying the same kind, rule, version, spans, and exact removed/replacement strings. Unchanged blocks emit no edit. Acceptance verifies reversal against the retained block bytes.

The detection struct is `{Version, Format, Original, Recipe}`, with `Format` `html` or `docx`. The converter observation struct is `{SchemaVersion, ArtifactHash, CandidateDigest, RequestDigest, RecipeHash, DetectorHash, DocumentHash, Outcome, Metrics, Findings}`. It always quarantines. Geometry then fidelity are mandatory unknown metrics with threshold `qualification-required`, reason `BASELINE_UNQUALIFIED`, zero counts, false pass, and nil evidence/exclusions. Blocking artifact findings include `GEOMETRY_UNKNOWN` and `FIDELITY_UNQUALIFIED`. M1.13 preserves these limitations; successful conversion cannot qualify them.

**Decision:** Derive a separate normalizer manifest from exported M1.12 constants.
**Why:** The frozen document type has no normalizer field, but revision and provenance rows require a distinct normalization digest.
**Rejected:** Reusing the converter digest or hand-typing rule names in composition.
**Detail:** `normalizer-v1` is `{SchemaVersion, Rules []{Rule, Version}, Transforms []string}`. Sort rules by `(Rule, Version)` and transforms by name. Merged M1.12 exports `NormalizationRuleNFCCRLF`, `NormalizationVersionNFCCRLF`, `TransformSourceDecode`, `TransformIdentity`, and `TransformNFCCRLF` in `normalization_contract.go`; `TestEmittedNormalizationConstants` in `normalization_contract_test.go` checks their emitted values. M1.13 freezes the codec. Every map transform and ledger rule/version must occur in the manifest. The baseline `parser-v1` is `{SchemaVersion, Parser}` with `Parser = none`; retain its bytes, not only its digest.

## Candidate manifests

A candidate freezes one attempt's selection. The input precedes conversion. The output follows successful conversion of every selected artifact. Ineligible work may have partial or no conversion; the roll-up identifies the exact available reports and missing ordinals.

`candidate-input-v1` fields follow this order:

| Field | Binding |
|---|---|
| `SchemaVersion` | `candidate-input-v1`. |
| `Country, DocumentVersionKey, ProcessingExecutionKey` | Origin execution's country, lease key, and execution key. On reclaimed replay resolve the original execution; do not rewrite the candidate. |
| `InputDigest, RecipeDigest, BudgetDigest` | Origin execution's frozen work digests. They are opaque execution identities, not automatically blob references. Budget JSON must equal registered work. |
| `ObservationKey` | Captured observation of this version with committed result provenance. |
| `Artifacts` | Array sorted by `(Role, ObservationOrdinal, ArtifactKey)`; its index is the candidate ordinal. Each entry is `{ArtifactKey, ObservationOrdinal, Role, Required, Capture model.CaptureRef, Format}`. Role/required/source ordinal match the observation-artifact link. Asset hash and format match the artifact; the full capture matches its committed capture result. Media type comes from that capture, not a nonexistent artifact column. `Format` may be empty as allowed by the source vocabulary. Candidate index `k` need not equal the source ordinal. |
| `Language, HTMLSelector, DetectorDigest, ConversionRecipe, NormalizerManifest, ParserManifest` | Native language, selected HTML region (`body` or an exact `#id` for HTML; may be empty for DOCX), detector recipe identity, then three recipe `AssetRef` values. Detector recipe identity is not a detection-result blob. |
| `GatePolicyDigest, ThresholdVersion` | Select the trusted policy. Reports cannot choose it. |
| `Mode, Predecessor` | `first_pass` with null predecessor, or `reprocess` with `{DocumentVersionKey, RevisionKey, CandidateDigest, AcceptanceWatermark}` for the same identity. |

The digest is every `CandidateDigest` and `candidate_digest`. Register the manifest and its execution edge before issuing conversion. `OriginalHash` in acceptance must equal an `Artifacts[*].Capture.Asset.SHA256`. Registration ties the candidate to the execution; acceptance compares the three work digests with the current work too. M1 does not decode unrelated execution input or orchestration recipe blobs to select policy. Selection must include every captured required artifact under the pinned source policy. Unresolved required capture inventory blocks M1 eligibility; quarantine records that gap without fabricating an original.

`candidate-output-v1` is `{SchemaVersion, CandidateDigest, NormalizerManifestDigest, GatePolicyDigest, TextHash, Artifacts}`. Each artifact is `{Ordinal, OriginalHash, DetectorDigest, RawBlocks, NormalizedBlocks, RawText, NormalizedText, OffsetMap, EditLedger}`. The six references are copied unchanged from `document.json`; detector digest names `detect-v1`. Ordinals cover the input exactly once in ascending order. `TextHash` hashes the rule A array of `NormalizedText.SHA256` values in that order. `OutputDigest` is this manifest's hash when present, otherwise the selected roll-up hash for ineligible work.

Revision minting uses the digest of the rule A sorted observation-key array for `source_observation_set_hash`, `TextHash` for `text_hash`, the observation's `metadata_digest` for `metadata_hash`, and converter/normalizer/parser/policy digests from the input. These derived or database metadata hashes need not be Bronze objects. The candidate digest remains attempt-specific. Document and sandbox-manifest hashes are attempt provenance, not revision identity; excluding them does not make the candidate output digest stable across new attempts.

## Policy and gate reports

`policy-bundle-v1` has these exact rule B keys:

| Key | Content |
|---|---|
| `schema_version, country, threshold_version` | Version, writer country, report threshold version. |
| `artifact_profile, rollup_profile` | Nonempty arrays sorted by `kind`, with unique `{kind, mandatory, allow_not_applicable, threshold}` entries. Explicitly map these snake-case fields to `model.MetricRequirement`; they are not its JSON encoding. Both profiles require geometry and fidelity. |
| `acceptance_limits` | Positive integers `max_blobs` (at most 1024), `max_rows`, `max_json_bytes`, `max_object_bytes`, `max_elapsed_ms`. M1.13 freezes these as configurable bounds with proposed, unmeasured defaults `1024`, `10000`, `4194304`, `67108864`, and `60000`, following the M1.11 `Limits` precedent. Owner gate O7 approves the production values before deployment and real-document acceptance; it does not gate the M1.13 code or its synthetic fixtures. |
| `gap_reason_codes` | Unique allowlisted reason strings in byte order. |

Gate metric arrays follow their profile order. Findings retain deterministic producer order, which M1.13 freezes in byte fixtures. The profile passed to `QualityReport.Validate` uses the resolved policy digest and mapped requirements. A metric must match its profile even in quarantine. Not-applicable requires profile permission and nonempty qualification evidence. Count and pass rules come from `model.QualityMetric.Validate`; no format-specific shortcut changes them.

`gate-report-v1` is `{SchemaVersion, Artifact model.QualityReport, RequestManifest *model.AssetRef, Document *model.AssetRef, OutputManifest *model.AssetRef}`. The last three are all present for a converted artifact and all null for an unconverted artifact. `Artifact.ArtifactHash` and `CandidateDigest` bind the input. Converted reports bind the retained request, its result document and sandbox manifest. Missing conversion requires a quarantining outcome and an explicit finding. All report fields follow frozen model spelling and order.

**Decision:** Encode `Artifact.Report` with a fixed self-reference sentinel.
**Why:** A blob cannot contain its own digest.
**Rejected:** Hashing with a real self-digest or silently ignoring arbitrary self-reference bytes.
**Detail:** The sentinel is exactly `{Path: "reports/self", SHA256: <64 zeros>, ByteSize: 0}`. Verify canonical bytes and this sentinel before substituting the real catalog-issued report reference in the local value passed to `QualityReport.Validate`. Never rewrite retained bytes.

`gate-rollup-v1` is `{SchemaVersion, CandidateDigest, OutputManifest *model.AssetRef, PolicyHash, ThresholdVersion, Outcome, ArtifactReports, MissingOrdinals, Metrics []model.QualityMetric, Findings []model.Finding, Gaps, Retained, DecisionRef}`. `OutputManifest` names the candidate output, or is null for incomplete conversion. Artifact reports are `{Ordinal, OriginalHash, Report model.AssetRef, Outcome}`, sorted by ordinal; every input ordinal has one report. `MissingOrdinals` is sorted and names reports without conversion. Gaps are `{Ordinal, Scope model.GapKind, ScopeKey, ReasonCode, Spans []model.Span}`. Retained entries are `{Ordinal, Spans []model.Span}`, one per input ordinal. Gap order is `(Ordinal, Scope, ScopeKey, ReasonCode)` with no duplicate tuple; gap/retained range spans sort by `(ArtifactHash, BlockID, Space, Range.Start, Range.End)` and may not overlap within a scope. Finding and metric span arrays retain producer order and can include unavailable ranges.

Retained and excluded spans use the artifact's aggregate normalized-text object, `BlockID = document`, `Space = normalized_text`, no token ordinal, and nonempty byte ranges with no reason. Each converted ordinal is partitioned without overlap or uncovered bytes. Empty or wholly missing text has empty retained spans and an explicit artifact/document-revision gap, never a fabricated zero-length span. Findings and metric evidence may also cite originals or per-block objects; preserve their native coordinate spaces and apply the projection rules below. A finding outside normalized text is not silently converted to aggregate offsets.

A missing conversion or a quarantining artifact report prevents eligibility. `needs_ocr` takes precedence when work requests OCR; otherwise failures, unknown mandatory metrics, blocking findings, or unapproved gaps yield `quarantined`. `accepted_with_gaps` requires a bound decision, complete conversion, passing retained-range metrics, no blocking findings, and exact gap scopes. `accepted` requires complete conversion, passing gates, and no gaps. `DecisionRef` is empty except for named-gap acceptance. Reserve its key before the gate rerun, then bind the resulting report hash in the decision row; never include that decision row's digest in the report.

## Projection into writer rows

M1.14 uses these rules; M1.6 recomputes them. Logical asset references retain their original paths. Adapter `blob.Metadata` values come from the catalog. Parent revision/version and candidate bindings come from the resolved target, and `processing_execution_key` is the original committed writer execution, never overwritten on replay.

| Rows | Deterministic projection |
|---|---|
| `conversion_artifact` | Five rows per candidate ordinal `k`: four document assets with roles `raw_blocks`, `normalized_blocks`, `raw_text`, `normalized_text`, plus `output_manifest` for the sandbox manifest. `ordinal = k`; `schema_version = blocks-v1` denotes the enclosing interchange. `original_hash = document.Original.Asset.SHA256`; converter/detector/candidate digests come from the document; normalizer digest from input. `manifest_hash` and size name the sandbox manifest for every role. |
| `ConversionArtifactInput.Members` | The five-role projection, sorted by role then ordinal, including the externally retained output manifest. This is an adapter role list, not the sandbox manifest's literal member array. The manifest does not list itself. Verify four assets are members; verify the fifth against the separately retained manifest digest. Other manifest objects enter closure without inventing more `00005` roles. |
| `offset_map_segment` | Segment `t` of artifact `k` emits source-major cross product edges; `transform_order = sum(len(OffsetMap[j]) for j < k) + t`, with `segment.Ordinal = t` checked in its blob. `segment_ordinal = sourceIndex * len(Destinations) + destinationIndex`. Group by source/destination hash pair and batch at most 1000 edges without renumbering. Preserve `map_hash`, transform, coordinates and anchors after the span projection below. |
| `edit_ledger` | Copy `Kind, Rule, Version`; `operation_ordinal = entry.Ordinal = i`; use the one input/output and their byte ranges. Read exact `Removed`/`Replacement` bytes and verify the `DecodedEdit` evidence. `source_anchors` is the rule A `Inputs` array unchanged, including empty block IDs; this JSON column does not call `conversionSpan`. Encoding/font evidence is `{}` for the baseline. SQL transport encodes bytea as hex; retained JSON is unchanged. |
| `quality_report` | Catalog report hash/size, selected policy, threshold, outcome; original artifact hash for artifact reports and NULL for roll-up. `record_count = len(Metrics) + len(Findings) + len(Gaps)`; artifact reports have no gap array. Parents may be NULL before revision minting. |

**Decision:** Number indexed transforms across the complete candidate in artifact order.
**Why:** The map UNIQUE key omits `map_hash`. Two originals with the same first paragraph can share a raw/normalized hash pair and local transform ordinal while their complete map hashes differ. Projecting local ordinals directly would conflict.
**Rejected:** Adding the map hash to the schema key or silently dropping the second artifact's map.
**Detail:** The prefix sum above gives each artifact a disjoint transform range without changing retained maps. Require a complete candidate output before writing map rows. Check all derived ordinals fit signed 32-bit columns and the row budget. Deduplicate identical ledger rows by their existing `(ledger_hash, operation_ordinal)` key; verify equal payloads before reuse.

**Decision:** Project map and report spans through the M1.5 `conversionSpan` constraints while retaining complete original spans in hashed objects.
**Why:** `00005` lacks token ordinals, and the adapter rejects non-nil `TokenOrdinal` and empty `BlockID` for maps and report `SourceSpans`.
**Rejected:** Dropping source anchors from M1.12, changing frozen types, or reopening M1.5 to add a column.
**Detail:** Clear `TokenOrdinal`. Replace only an empty `BlockID` with reserved ID `document`, which cannot collide with generated `block-` IDs. Map `decoded_package_member` to SQL `member_bytes`, and `raw_converter_text` to SQL `raw_text`; other spaces retain their spelling. Range pointers become start/end columns; absent page/object/member/reason values become SQL NULL. Report JSON keeps model space names. Preserve every other field. Ranged spans require empty reasons and valid byte bounds; unavailable ranges require `BYTE_MAPPING_UNAVAILABLE` and a usable page, object, or member anchor. Acceptance rejects any other difference.

Quality child ordinals run metrics, findings, then gaps, in their array order. Set fields as follows; every field outside the selected record kind is NULL:

| Kind | Fields |
|---|---|
| Metric | `code = string(Kind)`; copy metric kind/state/counts/threshold/mandatory/pass; `reason = ReasonCode` or NULL when empty. `source_spans` is projected `Exclusions`. |
| Finding | `code = reason = ReasonCode`; copy severity, scope, scope key. `source_spans` is projected `Spans`. |
| Gap | `code = reason = ReasonCode`; severity `warning`; copy scope and scope key. `source_spans` is projected `Spans`. |

Each record's `evidence` is the union of its declared `Evidence` and references for every span hash, deduplicated and sorted by hash. Gaps have only span-derived evidence. Use catalog-issued paths and exact sizes in projected `model.AssetRef` JSON. Never discard qualification evidence merely because no span names it. Empty evidence and span arrays encode as `[]`, not `null`. The report's retained bytes keep their logical references; acceptance performs the same catalog resolution before comparison.

The M1.5 adapter allows at most 1000 members, map edges per call, or report records, and 4 MiB of encoded input. Each edit's removed/replacement bytes is at most 1 MiB. Enforce these limits as well as policy limits before mutation. Oversized reports or edits reject without partial rows; do not claim that the M1.12 converter already emits a special report for this storage limit. M1.13 supplies a bounded quarantine report that records the limit.

## Catalog registration and execution retention

**Decision:** Add `ConversionCatalog.RegisterConversionOutputs` to `intake` before `document.Conversion` persistence in the `ApplyConversion` composition.
**Why:** Bronze writes belong to `intake`. The document adapter requires cataloged blobs and inserts no retention edges. A separate committed execution edge protects staged outputs before Silver persistence and acceptance.
**Rejected:** Bronze writes in `document`, registering only at acceptance, or nesting independently committing adapters.
**Detail:** Proposed constructor takes the transaction starter, writer identity, object store, and trusted limits. The method is `RegisterConversionOutputs(ctx, work run.IntakeWork, registration ConversionRegistration) (run.IntakeReceipt, error)`. Registration is `{Manifest blob.Metadata, Members []blob.Metadata, MemberRefs []model.AssetRef}`. It registers one bounded retained object set, not an assertion that those bytes pass a gate. Manifest parsing and projection remain in the producing composition; acceptance independently verifies them.

`Manifest` is the root object. `MemberRefs` is the complete direct dependency set for that operation, including already cataloged dependencies; `Members` supplies metadata only for new staged dependencies. Every supplied metadata item must match a reference by hash/size; a reference without metadata must already resolve in the catalog. A root cannot reference itself. Deduplicate by hash with equal sizes, retaining logical aliases for validation. Register root-only recipes first, then candidate input, retained request, sandbox outputs, candidate output, artifact reports, and roll-up. Every root and dependency receives an execution edge even when already registered or protected by another owner. Within one work attempt register each root hash once with its frozen metadata and reference set; reuse its receipt for identical bytes in another role. Originals additionally retain their existing observation edges.

Metadata sets media type from actual content, not from `objects/`: JSON for structured objects, UTF-8 text for text, declared type for decoded members, and the recipe's declared type for opaque recipes. Set `CaptureSource` to `candidate`, `conversion`, `quality`, `recipe`, or `decision`; `CaptureRef` to the producer envelope or execution key; `CapturedAt` to the retained production timestamp. These fields are required by `blob.Metadata.Validate`. Catalog winners retain their original metadata. Never overwrite an object or row to obtain a preferred path.

Work must be `DocumentIngest/intake/document_version`, stage `normalize`, substep `conversion-catalog`, shard equal to root digest, and decision revision zero. Freeze an immutable local `catalog-registration-v1` result payload `{SchemaVersion, Request run.IntakeApplyRequest, Registration ConversionRegistration}` in M1.15, with Go JSON field spelling/order and ordinary `time.Time` encoding in metadata; use a catalog-specific comparator for the registration and the frozen run comparator for work. The immutable registration includes its metadata timestamps and logical references. Sort `Members` by hash and `MemberRefs` by `(SHA256, Path)` before comparison; reject conflicting duplicate metadata. Retain these inputs unchanged for retries. Reuse exactly that registration after response loss. Changing the member set under one key conflicts even when catalog deduplication produces the same output set. This payload is producer M1.15's database result format, not a new model type.

**Decision:** Decode catalog receipts with a catalog-specific decoder, never with `receiptFromResult`.
**Why:** `receiptFromResult` unmarshals the whole stored payload into `run.IntakeApplyRequest`. The catalog payload nests the request under `Request`, so that helper returns a zero-valued `receipt.Result` without an error.
**Rejected:** Flattening the payload to reuse the helper (loses the immutable registration); patching `receiptFromResult` to sniff envelopes (changes `ledger.go`, outside M1.15); returning the caller's request instead of the stored one.
**Detail:** M1.15 freezes `catalogReceiptFromResult(ctx, tx, Result) (run.IntakeReceipt, error)`. It reads the result's execution key and transport receipts exactly as `receiptFromResult` does, decodes the payload as `catalog-registration-v1` with unknown-field rejection, verifies `SchemaVersion`, validates `Request` and `Registration`, and sets `receipt.Result` from `Request`. It preserves the original execution, result, and transport provenance. Fresh calls, identical replay, and reclaimed replay all return a receipt from this decoder over a fresh result read. A stored payload that fails decoding is an integrity error; never repair or re-encode it.

Transaction sequence, in one `ledgerTransaction` under the runtime login:

1. Validate shape and bounds before opening the transaction. Apply the stricter of trusted catalog limits and frozen work limits, including total object bytes and elapsed time. Lock admission `FOR SHARE`, then the one document-version lease `FOR UPDATE`; resolve execution, check work/budget and database time. Load the existing result before any catalog insert. Identical replay uses the original result execution key and existing edges; changed payload fails before object I/O. Neither path accepts a review decision.
2. Take the blob catalog guard below with `AcquireBlobCatalogGuard`, then recheck lease and time. Discover the complete root/dependency hash set without inserts. Lock all currently existing rows in SHA-256 byte order with new `LockCatalogBlob` (`FOR UPDATE`), retaining the locked IDs. Record missing hashes. A reference missing both catalog row and staged metadata rejects.
3. For new work only, insert missing rows in hash order with new `InsertCatalogBlob` (`INSERT ... ON CONFLICT DO NOTHING RETURNING id`). This separate query must distinguish own inserts from conflict winners; `RegisterSourceBlob` cannot. Under the guard no other guarded writer can commit a previously missing hash between discovery and insert, so a conflict winner signals an unguarded inserter. Treat it defensively: roll back and retry from discovery with a fresh transaction and the same grant, within the work deadline and at most three attempts, and record the retry count in test evidence. Do not lock or reference that winner after inserting other blobs. Replay never inserts or repairs rows.
4. Freshly read every resolved row with `ReadSourceBlob`. Compare size and derive physical references from the catalog; verify all bytes through cancellable bounded object reads. Recheck lease/time after every wait. All parents are now prelocked or inserted by this transaction. Only then add `execution` edges with `AddBlobRetentionReference`, in hash order, resolving conflict winners by a fresh read. Replay instead requires the original edges to exist.
5. Record one succeeded, nonterminal result: `Expected = Processed = Succeeded = 1`, other counts zero, no acceptance, cursor, decision or delivery, `OutputDigest = Manifest.SHA256`, and `Outputs` the unique catalog reference set in hash order. Use a fresh result read after insert; an unexpected winner forces rollback and replay, never a partial repair. Recheck lease and cancellation immediately before commit. Return the original receipt. Any rejection, expiry, cancellation, byte failure, or exhausted contention retry rolls back all new rows, edges, and result; sequence values may advance. Recheck time before returning a business conflict after a wait, so a stale grant takes precedence. Preserve aborted-transaction and cancellation causes without issuing further SQL.

**Decision:** Prelock existing blobs before any insertion.
**Why:** Inserts also acquire locks. Two sorted phases, register-all then lock-all, are not a safe global lock order.
**Rejected:** Register-all then lock-all; acquiring a new winner's row lock after other insertions; relying on deadlock retries as the normal order.
**Detail:** Let `A < B`, with A existing and B absent. Catalog inserts B. Capture holds A and waits in `RegisterSourceBlob(B)`. Catalog then waits for A: catalog → capture → catalog is a cycle. Prelocking A before inserting B prevents it. Prelocking cannot lock an absent row, so the guard below covers the absent-row case.

**Decision:** Serialize every transaction that may insert a `bronze.blob` row behind one transaction-scoped advisory lock, `pg_advisory_xact_lock(1129271888, 2)`, taken after the lease and every source accounting lock and before the first blob lock or insert.
**Why:** PostgreSQL makes a second inserter wait at the `sha256` unique index for an uncommitted first inserter, and that wait sits outside hash order. With shared hashes `A < B` and distinct leases: source transaction S prelocks absent A and B; another registration commits B; S inserts A; catalog transaction C locks existing B and waits at the index on A; S then reaches `AddBlobRetentionReference(B)`, whose `FOR UPDATE` waits for C. C cannot observe the winner until its insert returns, so the restart rule never runs. With the guard only one transaction holds uncommitted blob rows at a time, so no index wait exists.
**Rejected:** Restart on a concurrent winner alone; `FOR UPDATE` on `ingest.country_admission` (every writer holds it `FOR SHARE`, and a share-to-update upgrade deadlocks among admitted writers); a provisioned `ingest.acceptance_lock` row (adds an insert to every capture and bends that table's revision-key grammar); one advisory lock per hash (up to 1024 entries in the shared lock table and collision-dependent ordering); hash-prefix partitions (catalog sets span every partition, so M1 gains nothing); deadlock abort and retry as the normal path.
**Detail:** `1129271888` is the migrator's `CORP` class; id 1 is the session-level migration lock and id 2 is this guard. Two-int keys never collide with the 64-bit key of the `00004` identity lock ([advisory lock functions](https://www.postgresql.org/docs/17/functions-admin.html#FUNCTIONS-ADVISORY-LOCKS)). The lock is database-scoped, so it serializes one country writer. It releases at commit or rollback, has no manual release, and needs no table grant or row. The generated statement is `AcquireBlobCatalogGuard` (`SELECT pg_advisory_xact_lock(1129271888, 2)`, `:exec`) in `intake/queries/conversion_catalog.sql`. Source adapters call it in `prelockSourceAccounting` after `PrelockSourceRequests` and before `PrelockSourceBlobs`, only for the `DiscoveryAcceptance` and `CaptureAcceptance` payloads: `ApplyDiscoveryPage` and `ApplyCapture` are the two operations that reach `RegisterSourceBlob`. `AcceptDetail` delegates to `ApplyCapture` and inherits its registration and guard path. Other capture-bearing payloads insert no blob and take no guard. Catalog registration calls it at the start of step 2. Acceptance, revision, and conversion writers insert no blob and never take it. Recheck the lease and time after the guard wait. The guard is safe only with the parent prelock rule below.

**Decision:** Before the guard, resolve and lock `FOR UPDATE` every accounting parent the transaction body will lock, update, or reference through a foreign key; reject a required parent that is absent; let the body resolve parent identities only from that lock set.
**Why:** Host prelocking tolerated absent rows. With the guard alone: S prelocks its parents, host H is absent so `PrelockSourceHosts` skips it, and S takes the guard; `RegisterHost` creates H and commits; T prelocks H `FOR UPDATE` and waits for the guard; S reads H through the nonlocking `ReadSourceHostID` and inserts its request, whose `source_rate_limit_id` foreign key needs `KEY SHARE` on H, so S waits for T. A guard holder waited for an accounting row.
**Rejected:** Registering the host inside `ApplyCapture` (pacing policy belongs to `RegisterHost` under a window grant and is not in the capture payload); abort and restart (a restart cannot create the host, and the body already rejects an absent host); a late `FOR UPDATE` on the host in `registerRequests` (the out-of-order lock the rule forbids); applying the rule only to guarded payloads while the shared `registerRequests` keeps a second resolution path.
**Detail:** The rule applies to the three payloads that insert `ingest.artifact_request` or Bronze rows: `DiscoveryAcceptance`, `CaptureAcceptance` (`ApplyCapture`, and `AcceptDetail` through it), and `sourceRequestInventoryPayload` (`RegisterRequests`). Required parents are every window in the payload's window set and, for the two request-inserting payloads, the host of every `Requests[*].Plan.URL`. `prelockSourceAccounting` rejects an absent required parent with `grantError("prelock source parent", pgx.ErrNoRows)`, the same `ErrStaleGrant` class that `lockWindow` and `ReadSourceHostID` return today, before `AcquireBlobCatalogGuard` and before any insert. The only observable change outside the guarded operations is that `RegisterRequests` rejects an absent host at prelock instead of at `ReadSourceHostID`. Page-locator hosts stay tolerant: no foreign key reaches them, and `releaseDiscoveryHost` updates only hosts of issued claims, which were issued under the same window lease and therefore existed at prelock. The function returns `sourceLockSet{windows, hosts, requests, blobs map[string]int64}` holding the locked ids (`blobs` holds existing rows only). `sourceTransactionMode` hands the set to the body on `sourceLockedTx`, which embeds `pgx.Tx` as the `sourceInsertGateTx` test seam does; `sourceLocks(tx)` returns the set or fails closed. `registerRequests` resolves the window id and `hostID` from the set and returns an error before `RegisterArtifactRequest` for a key outside it; `ReadSourceHostID` is removed. `ApplyCapture` and `ApplyDiscoveryPage` compare the id returned by `lockWindow` with the set. A missing set or an unlisted key is an invariant error that issues no further SQL and rolls back.

Deadlock freedom under the guard. The global order is admission, lease, windows, pages, hosts, requests, guard, committed blob rows by hash, then own inserts and their child rows. A guard holder never waits for a lease or an accounting row: by the parent prelock rule every `ingest` row its body locks, updates, or references is a prelocked row it already holds, a row it inserted, or an `ingest.execution` row no runtime transaction can lock; a required parent absent at prelock rejects before the guard, and a parent committed after the prelock is never referenced because identities resolve only from the lock set. Between guarded writers the guard is the first shared resource and is single, so at most one has uncommitted Bronze rows; every later blob wait is `FOR UPDATE` on a committed row in hash order, and `AddBlobRetentionReference` reacquires a lock its transaction already holds or inserted. Non-inserting writers hold blob locks in hash order without the guard and insert no blob, so they never wait at the index or for the guard; a guard holder waits for them only on a committed blob in hash order. A `blob_retention_reference` key is never shared between a guard holder and acceptance, whose owner kind is `document_revision`. The shared-hash interleaving becomes: S takes the guard, prelocks absent A and B, inserts A then B, adds edges, commits; the other registration and C each block on the guard before any blob lock, then find A and B existing and lock both in order. The case with C first is symmetric. The absent-host interleaving becomes: S's prelock finds H absent and rejects before the guard, holding no lock on H; or H exists, S holds it `FOR UPDATE` before the guard, and T's prelock of H waits for S's commit while S waits on nothing T holds. The [acceptance lock table](corpus-database-acceptance.md#lock-order-and-concurrency-proof) names every competing writer path. Catalog takes their admission/lease prefix, the guard, and the existing-blob suffix, with no source window/page/host/request, Silver, identity, attempt, projection, or delivery lock. Ordinary ledger writers never wait for a blob before a lease. New rows are invisible to acceptance until commit. This proves no new reverse edge for the named paths; future cleanup needs its own review.

Throughput cost. Blob-inserting transactions in one country writer serialize from guard acquisition to commit, a window that holds hash-ordered blob locks, bounded object byte verification under `max_object_bytes` and `max_elapsed_ms`, and edge and result inserts. The guard serializes database transactions, not network requests: bytes are staged before the transaction opens, and the guard is held only inside it. This is acceptable in M1: O6 limits capture to one request per second and one in-flight request per host; transactions on one document lease already serialize on that lease, so the guard adds serialization only across documents and hosts within one country writer; each catalog call registers one bounded set and runs inside O7's processing ceiling; readers, acceptance, and Silver writers never take the guard; the alternative is a deadlock abort that repeats the whole transaction and its object reads. M1.14 records guard wait time in hosted evidence; a hash-prefix partition is a later measured change.

## Closure traversal and bounds

Start with candidate input, selected roll-up, optional candidate output, and optional decision scope. Follow only the typed references described here. Input adds each `Capture.Asset` and `Capture.TransportReceipt`, converter/normalizer/parser recipes. Output adds the six artifact assets and detector result. Roll-up adds candidate output and artifact reports. Artifact reports add request, document, and sandbox manifest when present. Request adds its capture and recipe. Sandbox manifest adds all members, including converter observations, per-block text, decoded members, maps, ledgers, and edit evidence.

Validate document, block, map, ledger, metric and finding references against that set. Add explicit report evidence assets as bounded typed dependencies, even when they are qualification evidence outside a sandbox manifest. Span hashes alone cannot introduce objects; each must resolve to a typed reference in closure. Decision scope adds no object beyond its bound candidate/report selection. Source observations resolve through immutable rows to captured payload and transport-receipt blobs. Metadata, source-tree, relation, observation-set, execution-input, and policy digests do not imply additional objects unless a typed reference explicitly names one. Inline policy remains a database dependency.

Deduplicate reads by hash; preserve logical path bindings for semantic comparison. Every selected object needs a catalog row, exact size, verified bytes at its physical path, and the required provenance-owned edge. Count root objects and dependencies against `min(policy.max_blobs, 1024)` and frozen work limits. Enforce total row, JSON, object-byte and elapsed bounds before allocation or reading. Unknown versions, unlisted references, missing provenance, or overflow reject rather than truncate. Eligible states require full conversion; missing ordinals are explicit only in ineligible reports.
